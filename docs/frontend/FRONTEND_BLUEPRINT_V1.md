# FRONTEND_BLUEPRINT_V1.md

## 문서 목적
이 문서는 Work Archive 프론트엔드의 **현재 canonical 설계 기준**을 정리한 문서다.

이 문서는 다음 역할을 가진다.
- 현재 코드에 이미 반영된 프론트 구조를 고정값으로 정리한다.
- 화면별 역할과 우선순위를 명확히 한다.
- 이후 UI 리팩터링과 세부 작업 분해의 기준이 된다.
- 기능이 추가되더라도 흔들리지 않는 기본 UX/IA 구조를 제공한다.

중요한 해석 원칙은 다음과 같다.
- 이 문서는 이상적인 미래 비전만 적는 문서가 아니다.
- 현재 저장소 코드에 이미 반영된 라우트/레이아웃/페이지 성격을 우선 반영한다.
- 다만 스타일 시스템과 세부 polish는 아직 미완료이므로, 현재 구조와 다음 단계 과제를 함께 구분해서 적는다.

---

## 1. 제품 정체성 고정값

### 1-1. 제품의 1순위 정체성
Work Archive는 **개인 취향 아카이브**다.

### 1-2. 제품의 확장 방향
Work Archive는 사용자가 본 작품을 정리하고 보여주는 것을 넘어, 나중에는 공유까지 가능한 **미디어 플랫폼**으로 확장되는 제품이다.

### 1-3. 초기 주요 타깃
초기 주요 타깃은 **가볍게 기록만 하는 유저**다.

### 1-4. 사용자가 느껴야 하는 핵심 인상
**기록이 정말 편하고, 내 취향이 정리되고, 필요하면 공유까지 자연스럽게 확장되는 서비스**

## 2. 최상위 정보 구조 (IA) 고정값

## 2-1. 메인 메뉴
다음 메뉴를 메인 제품 구조로 고정한다.
- 홈
- 작품
- 티어 보드
- 인사이트
- 커뮤니티
- 프로필

## 2-2. 계정/보조 기능 위치
다음은 메인 메뉴와 분리된 관리 맥락으로 고정한다.
- 계정 홈
- 동기화
- 설정

즉,
- 프로필은 **메인 제품 목적지**다.
- 계정/동기화/설정은 **Account 맥락의 관리 기능**이다.

## 2-3. IA 원칙
1. 홈이 시작점이다.
2. 작품은 기록/관리의 중심 기능이다.
3. 티어 보드는 작품과 연결되지만 별도 기능이다.
4. 커뮤니티는 메인 탭에 존재할 수 있지만, 중심은 여전히 개인 기록이다.
5. 동기화와 설정은 핵심 목적이 아니라 계정 기반 보조 기능이다.

## 3. 라우트/레이아웃 아키텍처 고정값

현재 프론트는 단일 셸 구조가 아니라, 아래 4개 레이아웃 맥락으로 분리된 상태를 기준으로 한다.

## 3-1. Main Product Layout
담당 영역:
- `/`
- `/works`
- `/works/new`
- `/works/:id`
- `/works/:id/edit`
- `/tier-boards`
- `/insights`
- `/community`
- `/profile`

역할:
- 메인 제품 경험 제공
- 홈, 작품, 프로필, 확장 기능 목적지 담당

## 3-2. Auth Layout
담당 영역:
- `/auth/login`
- `/auth/register`

역할:
- 로그인/회원가입 전용 흐름
- 메인 제품 셸과 분리된 인증 경험 제공

## 3-3. Account Layout
담당 영역:
- `/account`
- `/account/sync`
- `/account/settings`

역할:
- 계정 관리
- 동기화
- 설정
- 공개 범위 및 관리형 흐름 수용

## 3-4. Minimal Layout
담당 영역:
- `*` (404 등 최소 유틸리티 화면)

역할:
- 제품 목적지와 분리된 최소 화면 처리

## 3-5. 호환 리다이렉트 정책
기존 접근 동선을 위해 다음 리다이렉트를 유지한다.
- `/sync` → `/account/sync`
- `/settings` → `/account/settings`
- `/profile/sync` → `/account/sync`
- `/profile/settings` → `/account/settings`

## 3-6. 구조 원칙
- 메인 목적지와 계정 관리 맥락을 섞지 않는다.
- 로그인/회원가입은 메인 제품 내부 카드처럼 보이지 않게 한다.
- 404는 독립된 최소 화면으로 처리한다.

## 4. 페이지 템플릿 고정값

현재 페이지는 역할별 템플릿 성격을 갖는 구조로 해석한다.

- Home: 허브형
- Works: 워크스페이스형
- Work Create / Edit: 플로우형
- Detail / Profile: 디테일형
- Auth: 전용 인증형
- Account: 계정 관리형
- Minimal: 최소 유틸리티형

원칙:
- 같은 레이아웃 안에 있다고 같은 페이지 성격으로 취급하지 않는다.
- 페이지의 목적에 따라 header, CTA, 정보 밀도, 섹션 위계를 다르게 가져간다.

## 5. Home 설계 고정값

## 5-1. Home의 역할
Home은 서비스 내부의 **허브**다.

## 5-2. Home의 핵심 목적
- 검색 또는 빠른 추가 진입
- 내 통계 요약 제공
- 최근 기록 확인
- 현재 상태 기준으로 가장 자연스러운 다음 행동 제안

## 5-3. Home의 성격
- 개인용 중심이다.
- 커뮤니티 피드처럼 과하게 시끄럽지 않아야 한다.
- 설명보다 행동이 먼저 보여야 한다.

## 5-4. Home 상단 구조
현재 기준으로 Home 상단은 아래 구조를 따른다.
1. 검색창 / 빠른 추가 CTA
2. 짧은 hero copy
3. 핵심 통계 4개
4. 최근 기록 섹션

## 5-5. Home 최근 기록
- 기본 노출 수: **6개**
- 홈에서는 최근 기록의 요약 확인까지만 담당
- 전체 관리와 필터링은 작품 화면에서 담당

## 5-6. Home 통계 요약 고정값
홈에서 우선 노출할 통계는 다음 4가지로 고정한다.
- 총 기록 수
- 평균 별점
- 완주 작품 수
- 하차/보류 수

## 5-7. Home 설계 원칙
- 홈은 랜딩 페이지가 아니라 내부 허브다.
- 설명 문구는 짧고, 이동 동선은 명확해야 한다.
- 과한 안내 카드보다 검색/통계/최근 기록이 우선이다.
- 사용자는 홈에서 바로 작품 기록 또는 작품 탐색으로 이동할 수 있어야 한다.

## 6. 작품(라이브러리) 설계 고정값

## 6-1. 작품 메뉴의 성격
작품 메뉴는 사용자의 기록을 관리하고 수정하는 **핵심 작업 공간**이다.

## 6-2. 작품 화면의 우선순위
1순위: 관리/수정 편의성
2순위: 표지 중심 감상

## 6-3. 작품 목록 기본 뷰
- 기본 뷰: **List View**
- 보조 뷰: **Grid View 지원**

## 6-4. 작품 목록에서 중요한 정보 순서
작품 목록 기본 Row는 다음 우선순위를 따른다.
- 표지
- 제목
- 타입
- 별점
- 상태

## 6-5. 작품 상태 체계
기본 상태 목록은 다음 4가지로 고정한다.
- 보는 중
- 완료
- 보류
- 하차

## 6-6. 작품 목록 빠른 수정 정책
목록에서는 다음까지만 빠른 수정 가능하게 한다.
- 상태
- 별점

한줄평과 리뷰는 상세/수정 화면 중심으로 관리한다.

## 6-7. 작품 삭제 정책
삭제는 곧바로 제거하지 않고 **휴지통 개념**을 도입한다.

## 6-8. 작품 화면 필터/뷰 정책
- 상태별 분류와 필터를 함께 지원한다.
- 검색 / 타입 필터 / 정렬을 사용할 수 있어야 한다.
- 휴지통은 작품 영역 내부의 별도 표면으로 취급한다.

## 6-9. 작품 화면 설계 원칙
- 많은 작품을 기록하는 사용자의 피로를 줄이는 방향으로 설계한다.
- 기록량이 많아질수록 List 기반 관리 효율이 중요하다.
- 관리 중심 UI를 유지하되, 표지와 감상 흐름도 유지한다.

---

## 7. 작품 상세 설계 고정값

## 7-1. 작품 상세의 성격
작품 상세는 **감상 기록 중심** 화면이다.

## 7-2. 작품 상세 상단 우선순위
다음 정보가 가장 먼저 보여야 한다.
- 표지
- 제목
- 상태
- 별점
- 수정 / 삭제 / 복귀 액션

## 7-3. 상태/별점 표시 원칙
- 상태와 별점은 모두 중요하되, 현재 제품에서는 빠른 감상 판단이 가능하도록 상단에서 함께 보여준다.
- 목록 화면보다 상세 화면에서 더 분명하게 확인되어야 한다.

## 7-4. 리뷰 구조
- 한줄평과 리뷰는 상세의 핵심 콘텐츠다.
- 리뷰는 길이 차이가 크므로 접기/펼치기 또는 preview 중심 구조를 허용한다.

## 7-5. 빠른 수정 정책
상세에서는 다음을 빠르게 바꿀 수 있다.
- 상태
- 별점
- 리뷰 편집으로 가는 진입

단, 상세의 핵심은 “수정 안내”가 아니라 “작품과 감상 기록”이다.

## 7-6. 공개 확장성
현재 단계에서 공유 기능은 핵심 축이 아니지만, 앞으로는 아래 정보가 자연스럽게 붙을 수 있어야 한다.
- 대표 한줄평
- 공개 리뷰
- 작품 집계
- 티어 보드 연결
- 공개 프로필 연결

## 7-7. 작품 상세 설계 원칙
- 작품 정보보다 감상 기록이 먼저여야 한다.
- 그러나 추후 공개/집계 페이지로 확장될 수 있도록 메타 정보 구조는 유지한다.
- 리뷰 공개, 커뮤니티 반응, 티어 보드 연결이 붙을 수 있도록 여지를 둔다.

## 8. 작품 추가 UX 설계 고정값

## 8-1. 작품 추가의 기본 방식
작품 추가는 다음 흐름으로 고정한다.

**검색 → 선택 → 자동 채움 검토 → 개인 기록 입력 → 저장**

## 8-2. 작품 추가 UX의 핵심 가치
가장 중요한 것은 **사용자의 입력 피로감을 최소화하는 것**이다.

## 8-3. 검색 소스 정책
- 최종적으로는 외부 API 기반 검색을 지향한다.
- 현재 구조는 이 흐름을 기준으로 설계되어 있다.
- 실제 외부 메타데이터 연동은 아직 미완료다.

## 8-4. 작품 추가 시 사용자가 직접 입력해야 하는 최소값
- 상태
- 별점
- 한줄평
- 리뷰는 선택
- 티어는 별도 기능이라 제외

## 8-5. 검색 결과 카드 표시 우선순위
- 표지
- 제목
- 작가
- 타입
- 짧은 설명
- 연재/완결/권수 같은 식별 보조 정보

## 8-6. 검색 후보 식별에서 중요한 요소
사용자가 헷갈리지 않게 하려면 다음 요소가 중요하다.
- 설명
- 연재/완결/권수
- 타입

## 8-7. 자동 채움 후 검증 정책
- 전부 검토 가능하게 한다.
- 단, 핵심 필드를 강조해서 검증 피로를 줄인다.

## 8-8. 저장 완료 후 흐름
저장 후 기본 흐름은 다음으로 고정한다.
- 계속 추가
- 방금 등록한 작품 보기

## 8-9. 작품 추가 설계 원칙
- 긴 폼을 먼저 보여주지 않는다.
- 검색과 선택이 가장 먼저 와야 한다.
- 입력보다 검토와 확정이 중심이 되는 UX를 만든다.
- 반복 기록 사용자가 빠르게 연속 등록할 수 있어야 한다.

## 9. 티어 보드 설계 고정값

## 9-1. 티어의 제품적 위치
티어는 작품 필드가 아니라, **완전 별도 기능**으로 간주한다.

## 9-2. 티어 보드의 목적
- 개인 기록용
- 공유용

## 9-3. 티어 보드 진입 구조
초기 진입은 **보드 목록 먼저** 보여주는 방식으로 고정한다.

## 9-4. 티어 보드 생성 방식
- 주제별 자유 생성 가능
- 예: 내가 본 라노벨 티어, 애니 티어 등
- 티어 이름도 템플릿을 시작점으로 하되 자유 수정 가능

## 9-5. 티어 템플릿 정책
초기 기본 템플릿은 다음으로 고정한다.
- S
- A
- B
- C
- D
- E
- F

## 9-6. 티어 편집 구조
- 기본은 보기 모드
- 편집 버튼을 눌렀을 때 편집 모드 진입

## 9-7. 티어 보드 공개 정책
공개 범위 선택을 지원한다.
- 링크 공유
- 프로필 공개 탭 포함
- 커뮤니티 노출 가능
- 공개 범위 선택 지원

## 9-8. 현재 해석
현재 티어 보드 화면은 제품 구조상 자리와 맥락은 확보했지만, 기능 완성도는 아직 낮다.

## 9-9. 티어 보드 설계 원칙
- TierMaker의 장점을 참고하되, Work Archive의 취향 정리 경험과 연결한다.
- 일반 작품 관리 화면과 티어 편집 화면은 같은 UX로 섞지 않는다.
- 보드 생성 구조, 드래그 편집, 공개 보드 구조를 핵심 참고 패턴으로 삼는다.

---

## 10. 커뮤니티 설계 고정값

## 10-1. 커뮤니티의 제품적 위치
커뮤니티는 장기적으로 확장되지만, **서비스의 중심은 여전히 개인 기록**이다.

## 10-2. 커뮤니티 탭 초기 구조
초기 커뮤니티는 **전부 섞인 허브형**으로 시작한다.

## 10-3. 커뮤니티 초기 핵심 섹션
우선순위는 다음과 같다.
- 인기 작품
- 최근 많이 기록된 작품
- 인기 리뷰

## 10-4. 커뮤니티의 분위기
- 조용한 정보형
- 가벼운 반응형
- 자신의 취향을 공유하고 작품을 추천하고 받는 형태

## 10-5. 현재 해석
현재 커뮤니티는 레이아웃 소유권은 확보했지만, 기능적으로는 placeholder 성격이 강하다.

## 10-6. 커뮤니티 공개 구조의 성격
작품 단위 집계, 대표 리뷰, 좋아요 많은 한줄평, 공개 프로필 연결 등 **정보형/가벼운 반응형** 구조를 우선한다.

---

## 11. 프로필/계정 설계 고정값

## 11-1. 프로필의 제품적 위치
프로필은 **메인 제품 목적지**다.

핵심 우선순위:
- 내 취향 소개
- 내 기록 요약
- 공개 확장용 슬롯

## 11-2. 계정 센터의 제품적 위치
계정 센터는 **관리 맥락**이다.

핵심 범위:
- 계정 상태
- 동기화
- 설정
- 공개 범위와 정책 관리

## 11-3. 분리 원칙
- 프로필은 사용자에게 보이는 목적지다.
- 계정 센터는 사용자가 관리하는 공간이다.
- 프로필과 계정 설정을 같은 화면에 섞지 않는다.

## 11-4. 공개 범위 정책
장기적으로는 항목별 공개를 지원한다.
후보 범위:
- 작품 목록
- 한줄평
- 리뷰
- 통계
- 티어 보드
- 즐겨찾기
- 활동 내역

## 11-5. 현재 해석
현재 코드는 프로필과 계정 센터를 분리했고, 계정/동기화/설정은 `/account/*`로 관리한다. 다만 공개 프로필 기능은 아직 구조적 슬롯 확보 수준이다.

---

## 12. 인증 설계 고정값

## 12-1. 인증의 제품적 위치
인증은 메인 제품 흐름에 종속된 보조 카드가 아니라, **독립된 전용 흐름**이다.

## 12-2. 인증 화면의 목적
- 로그인
- 회원가입
- 게스트 → 계정 사용 확장 안내

## 12-3. 인증 화면 원칙
- 입력 집중도가 높아야 한다.
- 메인 제품 내부 카드처럼 보여서는 안 된다.
- 설명은 짧고, 계정 전환 가치만 간결하게 전달한다.

## 12-4. 현재 해석
현재 `/auth/login`, `/auth/register`는 AuthLayout 아래에서 독립적으로 렌더링된다. 구조 분리는 반영됐지만, 카피와 시각 밀도는 더 정리할 여지가 있다.

---

## 13. 디자인 방향 고정값

## 13-1. 비주얼 톤
- 서브컬처 감성이 있는 다크 톤
- 감성 강도는 **적당히**
- 기록 서비스로서 신뢰감과 정돈감을 우선

## 13-2. 디자인 기준
- 정보 스캔성이 좋아야 한다.
- 과한 장식보다 명확한 위계를 우선한다.
- 설명문으로 UX를 보정하지 않는다.
- 카드와 배지를 남용하지 않는다.

## 13-3. 참고 서비스에서 가져올 요소
- Steam에서 가져올 것:
  - 다크 톤
  - 카드 배치
  - 정보 밀도
  - 상세 상단 구성
- dc에서 가져올 것:
  - 가볍고 빠른 리스트성
  - 커뮤니티 감성
- TierMaker에서 가져올 것:
  - 보드 생성 구조
  - 드래그 편집
  - 공개 보드 구조

## 13-4. 카드 디자인 방향
- 기본은 **깔끔한 카드**
- 과한 장식보다는 정보 정리를 우선한다.

## 13-5. 절대 피할 것
- 설명 문구가 너무 많음
- 색이 너무 많음
- 관리자툴 느낌
- 투박한 표 형태
- AI나 초보가 만든 티가 남는 화면

## 13-6. 브랜드 표기
사용자에게 보이는 메인 브랜드 표기는 **Work Archive / 워크 아카이브**로 고정한다.

## 13-7. 현재 다음 단계
현재 가장 큰 UI 과제는 레이아웃 분리가 아니라,
- global.css 의존 축소
- Mantine 중심 UI 시스템 도입
- 공용 컴포넌트 체계 구축
- 설명형 카피와 카드 밀도 정리

이다.

---

## 14. 유지보수 및 확장성 원칙 고정값

## 14-1. 설계 분류 기준
설계도는 **기능 + 화면 혼합 기준**으로 나눈다.

## 14-2. 최우선 설계 가치
- 확장성
- 유지보수성
- 시각 일관성

## 14-3. 구조 원칙
- 현재 레이아웃 구조는 고정값으로 본다.
- 미래 기능이 들어와도 App Shell과 맥락 분리가 무너지지 않아야 한다.
- 작품 / 티어 보드 / 커뮤니티 / 프로필은 서로 연결되지만, 각자 독립된 경험을 가진다.
- 디자인 시스템과 공용 컴포넌트 체계를 먼저 세우고 페이지를 확장한다.

## 14-4. 제품 원칙
- 개인 기록이 중심이다.
- 공유는 자연스럽게 확장되는 방향으로 붙는다.
- 입력보다 선택과 검증이 중심이 되는 UX를 만든다.
- 관리가 쉬워야 오래 쓰게 된다.

---

## 15. 현재 가장 먼저 다뤄야 하는 화면
현재 기준으로 다음 3개를 최우선 화면으로 고정한다.
1. 홈
2. 작품 목록
3. 작품 상세 / 작품 추가

이 3개가 Work Archive의 첫인상, 기록 경험, 반복 사용성을 결정한다.

보조적으로,
- 인증
- 계정 센터

도 함께 polish 대상에 포함한다.

---

## 16. 설계도 v1 결론

현재 시점에서 Work Archive 프론트엔드는 다음 방향으로 고정한다.

- 시작은 홈에서 한다.
- 메인 목적지와 계정 관리 맥락을 분리한다.
- 작품은 List 기반 관리 효율을 우선한다.
- 작품 추가는 검색/선택/자동 채움 중심으로 설계한다.
- 작품 상세는 감상 기록 중심으로 설계한다.
- 프로필은 메인 목적지로, 계정/동기화/설정은 계정 센터로 분리한다.
- 티어는 별도 기능으로 분리한다.
- 커뮤니티는 정보형 허브로 시작한다.
- 디자인은 적당한 서브컬처 감성을 가진 다크 톤을 유지하되, 과하지 않고 깔끔하게 간다.
- 무엇보다도 사용자가 느끼는 핵심 가치는 **기록이 정말 편하다**여야 한다.

이 문서는 이후 세부 화면 설계, UI 시스템 정리, 프론트 리팩터링 실행 계획의 기준 문서로 사용한다.
