# AUTH_AND_GUEST_EXPERIENCE_STRATEGY.md

## 문서 목적
이 문서는 Work Archive의 **로그인 / 회원가입 / 게스트 사용 경험 전략**을 정리한 제품 문서다.

이 문서는 다음 질문에 답한다.
- Work Archive에 가장 잘 맞는 인증 전략은 무엇인가
- 게스트 모드는 유지해야 하는가
- 구글 로그인은 어떤 역할로 두어야 하는가
- 로그인과 회원가입을 어떻게 단순화해야 하는가
- 게스트 기록을 계정으로 어떻게 자연스럽게 넘겨야 하는가

이 문서는 현재 인증 구현 현실을 직접 설명하는 문서가 아니라, **앞으로 Work Archive가 채택해야 할 최적의 인증/게스트 UX 방향을 고정하는 제품 전략 문서**다.

---

## 1. 최종 결론

Work Archive에 가장 잘 맞는 인증 전략은 다음과 같다.

> **게스트 모드는 유지하고, 구글 로그인은 메인 계정 진입 수단으로 사용하며, 회원가입/로그인은 하나의 “계속하기” 경험으로 단순화한다.**

즉,
- 첫 진입은 로그인 없이 바로 기록 가능해야 한다.
- 계정 전환은 `Google로 계속하기`가 중심이 되어야 한다.
- 전통적인 회원가입/로그인 분리는 사용자에게 최소한으로만 노출한다.
- 가장 중요한 UX는 “로그인” 자체보다 **게스트 기록을 계정으로 자연스럽게 가져오는 흐름**이다.

---

## 2. 왜 이 전략이 Work Archive에 맞는가

## 2-1. Work Archive의 본질은 기록 앱이다
Work Archive의 핵심은 사용자가 작품 기록을 **바로 시작할 수 있게 하는 것**이다.

따라서 첫 경험에서 가장 중요한 것은:
- 회원가입을 시키는 것
- 프로필을 채우게 하는 것

이 아니라,
- **바로 기록을 시작하게 하는 것**

이다.

---

## 2-2. 게스트 모드는 제품 강점이다
게스트 모드는 단순한 임시 모드가 아니라, Work Archive의 핵심 강점이다.

장점:
- 진입 장벽이 매우 낮다
- 기록 앱으로서 “지금 바로 써보기”가 가능하다
- 서비스 신뢰가 쌓이기 전에도 사용자가 부담 없이 접근할 수 있다

따라서 게스트 모드는 제거 대상이 아니라 **정식 사용 모드**로 유지해야 한다.

---

## 2-3. 계정 전환은 최대한 쉬워야 한다
게스트 모드는 시작용으로 좋지만,
다음 단계로 넘어가는 경험은 더 쉬워야 한다.

사용자는 다음 시점에 계정 전환 의사가 생긴다.
- 기록이 쌓였을 때
- 동기화가 필요할 때
- 다른 기기에서도 이어 쓰고 싶을 때
- 향후 공개/공유 기능을 쓰고 싶을 때

이때 이메일/비밀번호보다 더 적은 마찰을 주는 방식이 **구글 로그인**이다.

따라서 구글 로그인은 선택 기능이 아니라, **계정 전환을 위한 메인 UX**가 되는 것이 좋다.

---

## 3. 최종 인증 구조

## 3-1. 기본 구조
Work Archive의 최종 인증 구조는 아래처럼 고정한다.

### A. 게스트 모드
- 로그인 없이 바로 사용 가능
- 기록 시작용 진입점
- 로컬 우선 사용 경험의 핵심

### B. 구글 로그인
- 메인 계정 진입 방식
- 사실상 회원가입/로그인을 통합한 `계속하기` 흐름
- 동기화/백업/다기기 사용/향후 공개 기능의 입구

### C. 이메일/비밀번호
- 초기에 유지할지, 이후 제거할지는 별도 판단 가능
- 그러나 장기적으로는 “메인 인증 UX”가 아니라 fallback 또는 보조 수단으로 보는 것이 좋다

---

## 3-2. 회원가입과 로그인의 UX 해석
Work Archive에서는 전통적인 의미의
- 회원가입
- 로그인

을 사용자가 크게 의식하지 않게 만드는 것이 좋다.

권장 UX는 다음과 같다.
- 처음 구글 로그인을 하면 자동으로 계정 생성
- 다시 구글 로그인을 하면 기존 계정 로그인

즉, 사용자에게는 `Google로 계속하기` 하나의 경험으로 보이게 한다.

---

## 4. 게스트 모드 설계 원칙

## 4-1. 게스트 모드는 정식 사용 모드다
게스트에서 가능한 것:
- 작품 추가
- 작품 수정
- 작품 삭제/복원
- 작품 목록 보기
- 작품 상세 보기
- Quick Add 사용
- 기본 홈/작품/상세 흐름 대부분 사용

즉, 게스트 모드는 “데모”가 아니라 **실제 사용 가능한 모드**로 유지한다.

---

## 4-2. 게스트 모드의 제한
게스트에서 제한할 것:
- 계정 기반 동기화
- 다기기 사용
- 계정 백업
- 향후 공개 프로필/공유 기능
- 공개 티어 보드 등 계정 기반 기능

핵심은,
- 기록은 게스트에서도 자유롭게
- 보관/동기화/공개는 계정 기능으로

명확히 나누는 것이다.

---

## 4-3. 게스트 모드 사용자에게 반드시 알려야 하는 것
사용자는 게스트 상태에서 아래를 분명히 이해해야 한다.
- 지금 기록은 이 기기에 저장되고 있다
- 로그인하지 않아도 기록은 가능하다
- 로그인하면 동기화할 수 있다
- 나중에 지금 기록을 계정으로 가져올 수 있다

즉, 게스트는 “불안한 임시 상태”가 아니라 **안심하고 써도 되는 시작점**이어야 한다.

---

## 5. 구글 로그인 설계 원칙

## 5-1. 구글 로그인은 메인 CTA다
로그인 진입 화면의 주 버튼은 아래처럼 고정한다.

- `Google로 계속하기`

구글 로그인은 Work Archive의 **주 계정 진입 경험**으로 사용한다.

---

## 5-2. 왜 구글 로그인이 메인인가
이유:
- 입력 마찰이 낮다
- 계정 생성과 로그인 경험을 자연스럽게 통합할 수 있다
- 동기화/백업이 필요한 시점에 전환율이 높을 가능성이 크다

즉, Work Archive의 계정 전환은 “가입”보다 **자연스러운 계속 사용** 경험이어야 하므로, 구글 로그인이 잘 맞는다.

---

## 5-3. 구글 로그인만 강제하지 않는 이유
구글 로그인은 메인이어야 하지만, 제품 전략상 중요한 것은 여전히 **게스트 모드 유지**다.

즉, Work Archive는 “구글 계정 있어야 쓸 수 있는 앱”이 아니라,
- 게스트로 시작 가능하고
- 만족하면 구글 로그인으로 확장하는 앱

이어야 한다.

---

## 6. 로그인/회원가입 화면 전략

## 6-1. 전통적인 로그인/회원가입 분리 축소
Work Archive는 아래 두 화면을 강하게 분리하지 않는 쪽이 좋다.
- 로그인
- 회원가입

대신 하나의 인증 진입 경험으로 묶는다.

권장 구조:
- 메인 CTA: `Google로 계속하기`
- 보조 CTA: `이 기기에서 바로 시작하기`
- 필요 시 작은 링크 수준의 이메일 로그인/회원가입

---

## 6-2. 인증 화면의 역할
인증 화면은 사용자를 설득하는 긴 마케팅 페이지가 아니다.

인증 화면의 핵심 역할:
- 계정 전환
- 기록 보관 가치 전달
- 동기화 가능성 전달

짧은 보조 문구 예시:
- 로그인하면 기록을 동기화하고 다른 기기에서도 이어서 사용할 수 있어요.
- 지금까지 기록한 작품을 계정에 저장할 수 있어요.

---

## 7. 가장 중요한 UX: 게스트 기록 이관

이 문서에서 가장 중요한 설계 포인트는 이것이다.

> Work Archive의 핵심 인증 UX는 “로그인” 자체가 아니라, **게스트 기록을 계정으로 자연스럽게 가져오는 것**이다.

---

## 7-1. 왜 중요한가
현재 구조상 게스트 아카이브와 계정 아카이브는 분리된다.

따라서 게스트 사용 중 로그인하면 사용자는 쉽게 아래처럼 느낄 수 있다.
- “내 기록이 사라졌나?”
- “로그인했더니 새 계정처럼 보이네?”

이 경험은 서비스 신뢰를 크게 떨어뜨린다.

따라서 로그인 순간 반드시 아래가 필요하다.
- 게스트 기록 존재 여부 확인
- 계정으로 가져올지 선택
- 가져온 후 어디로 갔는지 명확한 안내

---

## 7-2. 권장 이관 흐름
### 경우 A. 게스트 기록 없음
- 로그인 완료
- 바로 계정 아카이브 시작

### 경우 B. 게스트 기록 있음
로그인 직후 안내:
- `이 기기에 기록한 작품 12개를 이 계정으로 가져올까요?`

선택지:
- `내 기록 가져오기`
- `새 계정으로 시작하기`

추천 기본값:
- `내 기록 가져오기`

---

## 7-3. 이관 후 기대 결과
- 계정 아카이브로 전환
- 기존 게스트 기록이 보존됨
- 이후 동기화 가능
- 사용자는 “로그인하면서 기록이 안전하게 이어졌다”고 느껴야 함

---

## 8. 게스트 → 계정 병합 정책

초기에는 병합 규칙을 지나치게 복잡하게 만들 필요는 없다.

## 8-1. 초기 MVP 전략
가장 현실적인 초기 전략:
- 기본적으로 게스트 기록을 모두 계정으로 가져오기
- 애매한 중복 정리는 나중으로 미루기

즉, 초기에는:
- `로그인 후 기록을 잃지 않는 것`

이 가장 중요하다.

---

## 8-2. 향후 병합 고도화 방향
나중에는 아래 기준을 검토할 수 있다.
- 제목 + 타입 + 작가 유사도
- 최신 수정 시간 우선
- 리뷰/별점이 비어 있지 않은 값 우선
- 애매하면 “둘 다 유지 / 기존 덮기” 선택

그러나 초기 단계의 목표는 정밀 병합보다 **전환 불안 제거**다.

---

## 9. 로그인 / 비로그인 사용자 차이 설계

## 9-1. 비로그인 사용자
비로그인에서도 아래는 가능해야 한다.
- 작품 기록
- 목록 관리
- 상세 보기
- Quick Add
- 감상 정리

비로그인에서 제한되는 것:
- 동기화
- 다기기 사용
- 계정 기반 백업
- 향후 공개/공유 기능

---

## 9-2. 로그인 사용자
로그인 사용자는 아래 가치를 얻는다.
- 기록 보관 안정성
- 동기화
- 다른 기기에서 이어 쓰기
- 향후 공개 프로필/공유/티어 보드 연결

즉,
Work Archive의 로그인 유도 문구는 “가입하세요”가 아니라,

> **기록을 안전하게 보관하고 다른 기기에서도 이어 쓰세요.**

에 가까워야 한다.

---

## 10. 추천 화면 구조

## 10-1. 첫 진입
핵심 버튼 두 개만 크게 둔다.
- `Google로 계속하기`
- `이 기기에서 바로 시작하기`

보조 문구:
- 게스트로도 바로 기록할 수 있어요.
- 로그인하면 기록을 동기화하고 안전하게 보관할 수 있어요.

---

## 10-2. 게스트 사용 중 계정 전환 유도
자연스러운 전환 시점:
- Sync 페이지
- Account 진입 시
- 기록이 일정 개수 이상 쌓였을 때
- 다른 기기에서 이어 쓰고 싶을 가능성이 높은 시점

권장 문구 예시:
- 기록을 동기화하려면 로그인하세요.
- 지금까지 기록한 작품 8개를 계정으로 가져올 수 있어요.

---

## 10-3. Sync 페이지의 역할
게스트 상태에서는 아래를 명확히 보여준다.
- 현재는 이 기기에만 저장되고 있다
- Google로 로그인하면 동기화할 수 있다
- 지금 기록을 계정으로 가져올 수 있다

즉, Sync 페이지는 단순 제한 화면이 아니라 **계정 전환 설득의 핵심 지점**이 된다.

---

## 11. 하지 말아야 할 것

## 11-1. 게스트 모드 제거
게스트 모드는 Work Archive의 진입 강점이다. 제거하면 안 된다.

## 11-2. 구글 로그인만으로 시작 강제
구글 로그인은 메인 인증 방식으로 좋지만, 기록 앱의 첫 진입까지 강제하는 방식은 맞지 않는다.

## 11-3. 구글 로그인만 붙이고 이관 UX를 만들지 않기
이건 가장 위험하다. 로그인 후 기록이 사라진 것처럼 느껴지면 신뢰가 급격히 떨어진다.

## 11-4. 긴 회원가입 폼 중심 흐름 유지
이 프로젝트는 전통적인 가입 폼보다 “계속하기” 경험이 더 잘 맞는다.

---

## 12. 단계별 구현 우선순위

## Phase 1
- 게스트 모드 UX 개선
- 게스트 상태 안내 문구 정리
- 로그인 시 장점 메시지 정리

## Phase 2
- 게스트 → 계정 이관 플로우 설계 및 구현
- 기록 개수 안내
- 가져오기 / 새로 시작하기 선택지 제공

## Phase 3
- Google 로그인 도입
- 로그인/회원가입 흐름을 `Google로 계속하기` 중심으로 재구성

## Phase 4
- 이메일 로그인 유지 여부 판단
- 장기적으로는 fallback 수준으로 축소 가능

---

## 13. 최종 결론

Work Archive에 가장 잘 맞는 로그인/회원가입/게스트 전략은 다음과 같다.

1. 게스트 모드는 정식 사용 모드로 유지한다.
2. 구글 로그인은 메인 계정 진입 방식으로 사용한다.
3. 회원가입/로그인은 사용자가 크게 의식하지 않게 `계속하기` 경험으로 통합한다.
4. 가장 중요한 UX는 로그인 자체가 아니라, 게스트 기록을 계정으로 자연스럽게 넘기는 것이다.
5. 동기화/백업/공개 기능은 로그인 사용자에게 제공한다.

한 줄로 정리하면,

> **기록은 로그인 없이 시작하고, 저장·동기화·확장은 Google로 이어지는 구조**

가 Work Archive에 가장 잘 맞는 최적안이다.

이 문서는 이후 인증 화면 리디자인, 게스트 모드 개선, 구글 로그인 도입, 계정 전환 UX 설계의 기준 문서로 사용한다.
